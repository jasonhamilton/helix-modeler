# Scripts

Small utilities the skills call. Most are built during the spikes by the agent that owns the skill; until then a skill says "build it to the contract first". Present today:

- `ledger_append.py` — append one row to `ledger/runs.csv` (see `contracts/ledger-format.md`).
- `stomp_spike_probe.py` (stomp-engine, T003) — hardware spike probe: find the Stomp's audio and MIDI ports, play a synthetic probe to USB 5/6 and record USB 1/2, compare two captures, send a CC or Program Change. Runbook in `docs/notes/T003-stomp-control-spike.md`.
- `stomp_inject.py` (stomp-engine, T018s): whole-preset injection spike. `gen` makes and validates the known.hlx variants for fw 3.50 in `cache/stomp/inject/`; `compile --base <backup.bin> [--variants ...]` compiles them offline (`TONEMATCH_STOMPD_COMPILE`) and checks every parameter and snapshot controller value of the result against the .hlx (`stompd decode`, T051; exit 1 on a mismatch); `run [--no-render]` writes each into the edit buffer (op 21), reads back and diffs every parameter (`stomp_readback`; the engine's `load()` raises `ReadbackMismatch` first), renders di_2s, restores 04C and byte-diffs against the backup. Results in `docs/notes/T003-stomp-control-spike.md` (T018s).
- `reamp_capture.py` (stomp-engine, T004): skill `reamp-capture`. `--calibrate` measures the impulse latency and level gain and writes `cache/stomp/latency.json`; `<dry.wav> --out <wet.wav>` reamps through the Stomp (USB 5/6 in, USB 1/2 out), trimmed and level-matched; `--user-di --play <song> --section A:B --target A:B --countin 4 --takes N` is the play-along DI capture (T042). It plays a count-in on the song's beat grid and then the section on USB out 1/2 (the Stomp's outputs and phones), and records dry USB in 5/6 and wet USB in 1/2 in the same stream. Each take is trimmed by the calibrated round trip to the song timeline and saved as `cache/user_di/<song-id>/take<k>_{dry,wet}.wav` plus `take<k>.json` (alignment, levels, clipping, silence and bleed checks; exit 3 if the dry is digital zero). It only reads the pedal, and `--dry-run` plans without the device. The maths is in `src/tonematch/user_di.py`; the tests are `tests/test_user_di.py`. Uses the `stompd` control helper through `TONEMATCH_STOMPD` when it is present, and puts back every edit-buffer change it makes.
- `native_spike.py` (native-engine, T002) — host Helix Native, dump and scan its saved state for a preset document, prove a state round trip or probe the 16+16 automation params, measure render cost; `--capture-template` saves a chain template for the automation route. Exit 2 if Native is not installed. Runbook in `docs/notes/native-spike.md`.

- `loss_trust_check.py` (tone-metrics, T022): skill `loss-trust-check`. `--proxy --all [--ledger]` ranks the true preset against distractors per loss term on offline numpy DSP proxy data (dataset `proxy-dsp-v0`, NOT Helix, not admission evidence); without `--proxy` it needs `fixtures/synthetic/manifest.json` and exits 2 until benchmark builds it.
- `status_report.py` (status-reporter): skill `status-report`; implements `docs/STATUS-REPORT-SPEC.md`. Builds ONE report model from `docs/features.json` (per-feature registry), `docs/status-curated.json` (curated judgements: health, technical progress, readiness, problems, human actions, milestone text, glossary, evidence ids), `board/GATES.md` (milestones and criteria), the board, ledger and git, then renders `reports/status/index.html` (dashboard, no JavaScript) and `reports/status/README.md` (standalone Markdown) and saves `reports/status/history/<date>.json` (small snapshot the next report diffs against). Options: `--run-checks` (pytest, ruff, licence check), `--format html|md|html,md`, `--no-snapshot`, `--json <path>` (dump the model), `--curated`, `--registry`. Exits 2 with a list of problems if the registry or curated file is invalid or contradicts the gates (health On Track with a Critical issue, Validated without Gate 2 signed, a human need in the registry that no action covers, duplicate actions, unknown evidence ids, an over-long or jargon-filled summary). No completion percentages are reported. Standard library only.

- `engine_smoke.py` (benchmark, T008): skill `engine-smoke`. Detects an engine, renders `fixtures/smoke/di_2s_real.wav` (real Guitar-TECHS DI, dataset `smoke-real-di`; synthetic `di_2s.wav` fallback, dataset `smoke`, `--di`) and checks level, silence, NaN and length; `TONEMATCH_ENGINE=native|stomp|auto`; exits 2 with no row if no engine is present.
- `catalog_import.py` (preset, T005): reads the model definition files from the user's own HX Edit install into `cache/catalog/`; nothing is copied into the repo.
- `hlx_validate.py` (preset, T006): parses and validates an `.hlx` (blocks, DSP cost, amp/cab pairing, device version); also runs the byte-equal round trip.
- `make_smoke_hlx.py`, `make_smoke_di.py` (preset, benchmark): generate the local smoke preset and the synthetic smoke DI under `fixtures/smoke/`.
- `native_render_probe.py` (native-engine, T026): measures Native render cost (reset and flush modes, clip length, pool scaling); writes ledger `render-cost` rows with `--ledger`. Findings in `docs/notes/native-spike.md`.
- `native_capture_bench.py` (native-engine, T055): times Native chain captures step by step, the old one-host-per-file flow (`before`) against one editor session per host (`after --sessions N --verify auto|per-cc|truth`), on single-block library chains at catalog defaults (breadth-first order: drive, delay, reverb, comp, EQ, mod) and `--c8`; `check` replays two runs' templates in fresh hosts. Results in `cache/native/capture_bench/`.
- `native_cc_grid_probe.py` (native-engine, T055): which value Native gives a param when its MIDI CC is at c/127 (linear `lo + c/127 (hi - lo)`, bit-exact; log and c/128 miss). Results in `cache/native/cc_grid_probe/`.
- `native_pool_bench.py` (native-engine, T055): tests/s of `NativeRenderPool` per host count (`--hosts 2,4,6,8,10 --clips 2,10 --renders 100 --score`), per-test latency, footprint per host, memory pressure level and swap, watchdog recycles, canary replacements, bit-identity spot check against a single engine; stops when pressure turns red or swap grows; `--ledger` writes `render-cost renders_per_s` rows. Results in `cache/native/pool_bench/`.
- `separate.py` (separation, T020): skill `separate`. htdemucs_6s by default with backend detection; the RoFormer path is opt-in and needs `TONEMATCH_ROFORMER_LICENCE_ACK=1`.
- `search_smoke.py` (search, T023): Native smoke demo of `match()`; a timing and plumbing check, not a benchmark.
- `synthetic_benchmark.py` (benchmark, T024): generates the labelled synthetic-v1 manifest (labels only, written under gitignored `cache/synthetic/`); it cannot render the set until the human captures three Native chains.
- `licence_check.py` (reviewer, T011/T016a): scans dependency licences, the pedalboard import boundary, Line 6 assets and committed golden presets; allowlist in `docs/licence-allowlist.json`; writes `reviews/licence-<date>.md` (`--no-write` to skip).

- `match_song.py` (search, T041): end-to-end match of one song section on Native, LOCAL ONLY. Picks the most guitar-dominant 10 s of a snapshot from the stems and the separator's confidence mask, picks DI clips with `dry.pick_di`, runs a beam over the Native chains that have templates (K A B0 B A30 C H) then CMA-ES on the best two, final-checks the top 3 with stems and mask, writes the best as a fw 3.50 `.hlx` (validated), a level-matched listening pack (`listen/`, with an L=target R=match file) and `report.md`. Every loss is labelled `unadmitted loss`. Objective adds a level guard and a weak neutral prior (`--level-tol-db`, `--prior-weight`); the Native host is restarted on death or past `--rss-limit-mb`. `--dry-run` picks target, DI and chains and renders nothing. Run: `TONEMATCH_NATIVE_PYTHON=cache/native/hostvenv/bin/python python scripts/match_song.py --wall-min 25`. Writes no ledger row (no suitable `kind` yet; `match` proposed).
- `benchmark_suite.py` (benchmark): runs the whole benchmark suite in a fixed order (engine smoke Native and Stomp, hardware parity on K, A, B0, B00, BT0, proxy loss trust check on seeds 9301/9302, synthetic recovery, separation stress, block-probe validate, pytest, ruff), times each with wall-clock, writes `reports/benchmark/history/<UTC stamp>.json` + `latest.json`, one `kind=benchmark dataset=suite metric=suite_wall_clock_s` ledger row, and regenerates the "most recent benchmark run" section of `docs/BENCHMARKING.md`. `--only/--skip <ids>`, `--no-hardware` (Stomp tests: skipped, no pedal), `--no-ledger`, `--render-doc` (refresh only the doc section), `--list`. Run from the human's Terminal for the Stomp tests (HX Edit closed). Tests: `tests/test_benchmark_suite.py`.
- `parity_null.py` (benchmark): skill `parity-null`. `gen` writes presets C (clean) and H (high gain + fixed-time delay) beside the four T018s variants in `cache/stomp/inject/`, validates all six for fw 3.50 and cuts `cache/parity/di_10s_tail.wav` (10 s Guitar-TECHS + 2 s silence); `check` is offline (it warns when a file's snapshot controller values differ from its blocks, and with `--base <04C backup.bin>` compiles each preset and checks every parameter of the result, T051); a Stomp load that does not read back as the .hlx says raises `ReadbackMismatch` and that preset is not rendered (summary `engines.stomp.readback`); `run` writes each preset whole into the Stomp's edit buffer (`whole_preset="always"`), renders, restores 04C and byte-diffs, then loads the SAME `.hlx` into Native (`TONEMATCH_NATIVE_AUTOCAPTURE=1`), renders, aligns (fractional lag), level-matches and nulls. Outputs under `cache/parity/<stamp>/`: `<name>_stereo.wav` (L = Stomp, R = Native), `<name>_residual.wav`, `<name>.json`, `summary.json`, raw renders in `raw/` (`--out-dir ... --reuse` resumes); ledger rows kind=parity, engine=both, dataset=parity-v0 (`null_residual_db`, `stomp_to_native_gain_db`, `restore_bytes_equal`). Run: `TONEMATCH_STOMPD=cache/stomp/bin/stompd TONEMATCH_STOMPD_COMPILE=cache/stomp/bin/stompd-compile python scripts/parity_null.py run` (HX Edit quit; `--no-ledger` for a rehearsal).

- `block_probe.py` (tone-metrics, T046): skill `block-probe`, offline part. `make` writes the probe set `cache/probe/probe-v1.wav` (47.25 s, float32 48 kHz: ESS at 4 levels, stepped sines, two-tone, level steps, bursts, gate staircase, impulse, 3 Guitar-TECHS DI excerpts read from `data/di` and never copied, end sync marker) and its layout JSON; `analyse <wet.wav>` turns a single-block render into a fingerprint JSON (schema in `docs/notes/block-probe.md`); `compare A.json B.json` diffs two fingerprints per feature (exit 1 if any differ beyond tolerance); `validate [--ledger]` checks the analysis against known numpy/scipy blocks and prints the accuracy table. Renders nothing: rendering through Native or the Stomp is T047.

Expected soon (owner in parentheses): `ab_session.py` (benchmark).
- `block_coverage_report.py` (benchmark, T057): regenerable Stomp-versus-Native block coverage report, run at step 8 of the `cycle` skill. Reads the local catalog, every rendered or captured preset, the parity runs, search results and the ledger; writes `reports/local/blocks/index.html` (dashboard by GUI category, tested models with the settings tried, a card per tested chain with inline SVG charts) and `README.md`. LOCAL ONLY (it names Line 6 models; `reports/local/` is gitignored) and it refuses to write anywhere else. Options: `--root`, `--out` (must stay under `reports/local`), `--format html,md`, `--json`. Standard library plus numpy, scipy, soundfile.
- `mod_calibrate.py` (tone-metrics, T116): calibration table for the modulation specialist. `render [--hosts 1|2]` renders 37 modulation models at their defaults and 40 random settings on two passages of the calibration DI (Guitar-TECHS P3_music directinput_04; at most 2 Native hosts and never more than 6 on the machine; resumable); `build [--jobs 2]` computes the specialist's features and writes `cache/mod-specialist/calibration.json` (local, holds model ids). Re-run `build` after any feature change.
- `linear_tables.py` (tone-metrics, T117): response tables for the linear specialist. Renders a synthetic periodic probe through every cab and EQ model of the block library at a grid of knob settings (interacting knobs found from the renders; one-knob groups at all 128 CC steps), adds an LTI check, writes `cache/linear-tables/<library version>/` (local, holds model ids). One Native host, refuses above 6 on the machine; resumable (`--redo`, `--models`, `--only-pools`, `--lti-only`).
- `linear_eval.py` (tone-metrics, T117): `run --set synthetic-lindev --half tune|heldout|all` renders each item's target, runs the screen on every item and the linear specialist on cab and EQ items (held-out loss, family-score rank-1 rule B); `summarize --hybrid-tag TAG [--ledger]` adds the paired comparison against a `synthetic_v1.py run --hybrid` directory and writes kind=search and kind=loss-trust rows. One Native host.
- `mod_trust_check.py` (tone-metrics, T116): trust set `mod-trust-v1`. `gen` draws the registered set (refuses to redraw), `render` renders candidates and the LFO-shifted targets (at most 2 hosts), `score [--ledger]` ranks the true modulation preset against near misses, other modulation models and confusers with `mod_distance`, `mrstft_v2` and the family score, on aligned and LFO-shifted targets, rule B, and reports the specialist's measurements. Design and bars in docs/DECISIONS.md (2026-10-17, T116).

- `gain_trust.py` (tone-metrics, T144): gain-stage loss trust. `gen` draws `gain-trust-v1` (amp and drive, the truth vs 9 near, 4 gain-compensated pairs and 3 small moves, on helix-trust-v2's model and DI splits, avoiding the synthetic sets' DI excerpts) under cache/loss-trust/gain-trust-v1/; `render` (Native, at most 2 hosts, via helix_trust_v2's renderer and the host scaler); `features` (per candidate mrstft_v2, level_db, ltas_tilt, crest, envelope against the aligned capture, plus nulls; at most 2 processes); `eval --split fit|test --score term=w,...` (rule-B rank-1 per family, level-only diagnostics); `diag-v2` (DIAGNOSIS ONLY, the six Gate 2 attempt 2 misses).

Every script is classified and documented in `docs/TOOLS.md` (user-runnable tools with inputs, outputs, options and examples; internal helpers; historical spikes). Thirteen tools take `--result-json PATH` and write a machine-readable manifest for an agent (`contracts/cli-result.md`, `src/tonematch/cli_result.py`).
