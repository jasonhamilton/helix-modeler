### The tone comparison is not validated

**Critical** · Active Blocker

- **Problem.** The tool scores how close two guitar sounds are with several measures, and none has passed the required accuracy test on audio from the real Helix engines.
- **Impact.** The optimiser cannot be trusted to pick a genuinely matching preset, so Gate 2 cannot be passed and automatic matching cannot be offered. On the one real song, the top two candidates scored 6.935 and 6.950 (lower is better), a gap too small to mean anything, while the listener clearly preferred one; the best score also swung from 7.7 to 22.7 depending on which clean guitar recording was used.
- **Cause.** Measures were built and checked on non-Helix stand-in signals, where the best one chose the right answer first only about 1 time in 8. Real Helix audio has not yet been tried because the known-answer set has not been rendered. The score also ignores loudness.
- **Resolution.** Render the known-answer set through Native, run the trust check on each measure, and combine or replace measures until the agreed accuracy is reached.
- **Owner.** benchmark and tone-metrics, with the lead freezing the thresholds
- **Next step.** Render the known-answer set through Native and run the trust check on it.
- **Evidence.** Tone-comparison trust check on stand-in signals; Informal listening to the first real-song matches; Known-answer set design and working targets

### The pedal and Native disagree on one cabinet setting

**High** · Confirmed Problem

- **Problem.** The cabinet's Early Reflections setting does not sound the same on the pedal and in Native.
- **Impact.** A preset found on the fast Native engine can sound different on the real pedal. At the value the search chose, the two engines' recordings cancel by only 3.6 dB (poor agreement); with the setting at 0 they cancel by 31 dB (close agreement).
- **Cause.** Not yet known. Candidates are an older algorithm in the pedal, a different parameter scale, or a delay-structure difference. Other parameters tested at their extremes agreed.
- **Resolution.** Find the cause, or measure every searchable parameter on both engines and let the search free only the parameters that agree.
- **Owner.** native-engine and stomp-engine; benchmark for the per-parameter audit
- **Next step.** Run the per-parameter agreement audit; until then any preset meant for the pedal keeps this setting at 0.
- **Evidence.** Pedal versus Native agreement on four presets; Decision log

### Guitar separation quality on real songs is unknown

**High** · Unknown/Unverified

- **Problem.** The step that isolates the guitar from a full mix has only been scored on an artificial mix. One real song was processed without a quality score.
- **Impact.** If the isolated guitar contains drums, vocals or artifacts, the tone comparison will chase those instead of the guitar and Gate 3 results will be unreliable.
- **Cause.** No real-song stress set exists, and the only separation model aimed at guitar has no stated licence so it was not used.
- **Resolution.** Run the separation stress test on a few real songs, locally, and record how accuracy falls as the mix gets denser.
- **Owner.** separation, after the owner supplies songs
- **Next step.** Owner chooses the first songs (one action covers this and the Gate 3 song set).
- **Evidence.** Separation run on the real song (no quality score)

### The library of measured blocks does not exist yet

**Medium** · Risk

- **Problem.** The per-block approach needs every effect block measured through Native, and the measuring kit has never been run on Helix.
- **Impact.** Choosing amp and effect models from measurements (instead of trying them blindly) is not possible, which makes the search space larger than it needs to be.
- **Cause.** The measuring kit was only finished offline on stand-in blocks. Native's current host is mono, so stereo blocks and dual cabinets cannot be measured; one unexplained accuracy floor remains when an amp follows other blocks.
- **Resolution.** Render the measuring signal through Native for a few blocks first, set tolerances from repeat-render spread, then capture the library overnight for mono blocks.
- **Owner.** native-engine, then benchmark and search
- **Next step.** Build the Native rendering of the measuring signal.
- **Evidence.** Block-by-block rendering test; Block measuring kit on non-Helix blocks

## Glossary

| Term | Meaning |
|---|---|
| blind A/B | A listening test where the listener does not know which option is which. |
| block | One element in a preset's chain: an amp, cabinet, drive pedal, delay and so on. |
| CMA-ES | An optimisation algorithm used to search for suitable settings. |
| dB | Decibel, a logarithmic loudness or level-difference scale. |
| DI | Direct Input: a clean, unprocessed guitar recording, before any amp or effects. |
| DSP | Digital Signal Processing: the audio calculations inside amps and effects. |
| Early Reflections | A cabinet setting that adds the first short echoes of the room. |
| EULA | The software licence agreement shown when installing a product. |
| firmware | The software running inside the pedal. |
| gate | A milestone with a written checklist and a human sign-off. |
| held-out | Test items not used when tuning, so the result is not flattered by tuning. |
| Helix Native | Line 6's software version of the Helix sounds; it runs as a plugin and renders audio offline. |
| HX Edit | Line 6's editing program for the pedal; it also imports preset files. |
| HX Stomp | The Line 6 guitar-effects pedal this project targets. |
| known-answer set | A test set made by rendering presets we already know through Helix, so we can check whether the tool recovers them. |
| ledger | The project's append-only record of measured runs; a claim without a row did not happen. |
| loss | The score the optimiser tries to lower: how different two sounds are. Lower is a closer match. |
| MIDI CC | A control message that moves one knob or switch from software. |
| null residual | What is left when one recording is subtracted from another that should match. Reported in decibels below the signal; the more negative, the closer. |
| preset | A saved sound: a chain of amp, cabinet and effect blocks with their settings (an .hlx file). |
| readback | Reading the pedal's settings back after writing them to confirm they match. |
| separation | Splitting a full mix into instruments so the guitar can be analysed alone. |
| snapshot | One of up to three stored variations of a preset that the pedal can switch between. |
| stand-in signals | Test audio made by ordinary software effects instead of Helix. Useful for early checks; not proof the method works on Helix. |
| tone comparison | The loss: the combined measures of how similar two guitar sounds are. |
| trust check | A test of whether a measure puts the true preset first among many candidates. |
