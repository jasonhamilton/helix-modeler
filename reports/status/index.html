Generated 2026-10-14 22:32 UTC · Cycle 3 (mode 2), end of cycle refresh; board/CYCLES.md has a cycle 3 entry (marked in progress) · for tone-matcher-lead (end-of-cycle refresh, second run of the status-report skill)

Both render engines can be driven from code and Gate 1 was signed on 2026-10-14: Helix Native 3.82 renders a captured chain (about 1.9 s per 2 s clip, fixed reset cost plus 0.045 s per second of audio) and the HX Stomp (firmware 3.50, macOS only) renders over USB (about 2.7 s per clip); a generated .hlx was accepted by HX Edit and loaded on the pedal. Around that sit unit-tested but unproven building blocks: a preset parser and validator, a guitar separator, a section segmenter, a reference-DI picker, a loss kit and a CMA-ES search that now plans serially against the real render cost. Since the first report the envelope loss term was rebuilt (v1) but on non-Helix proxy signals its held-out rank-1 is only 0.033 to 0.117 on fresh seeds, so it is still weak and no loss term is admitted (every default weight is 0). Nothing has been measured on real songs or on a Helix-rendered known-answer set; there is no song-to-preset command; Gates 2 and 3 have no evidence; nothing has been judged by ear. The human's next actions are to capture three Native chains, approve the synthetic-benchmark thresholds, download a DI set, give the go on the T018 spike and the AFx-Rep checkpoint, read the installer EULAs, decide the firmware and the project licence.

Challenges and findings

  • Whole-preset state write is impossible: the saved state is opaque high-entropy records in a CMXH container, and replayed library records are refused. Going further would mean attacking the cipher, which the interop-only rule forbids. [docs/notes/native-spike.md; DECISIONS 2026-10-14 cycle 2]
  • Every render is a reset render with a 4,800-sample pre-roll; reset costs about 1.6 s regardless of clip length, so cost() not clip length sets the budget. Measured on an empty preset and one chain: a lower bound. [DECISIONS 2026-10-14 cycle 2; ledger 16:37:06]
  • cost() was cached by raw-state hash; a knob move changes Native's raw state, so plan_budget re-ran a ~130-156 s measurement inside search's smoke demo (156 of 202 s). Fixed by keying on chain structure; demo went to 46 s, 2.4 s per render call, same answer. Loaded-machine runs (two foreign CPU-bound jobs) are 1.96 s, so timings vary about 5 percent with load. [DECISIONS 2026-10-14 native-engine T026; ledger 2026-10-14T21:02:08+00:00]
  • Throughput scales to about 2.3 renders/s at 6 to 8 workers; parallel use inside CI is not measured. [ledger 2026-10-14T16:57:53+00:00 notes]
