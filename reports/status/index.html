HX Stomp Tone Matcher: project status

Generated 2026-10-15 19:52 UTC · Cycle 4 (mode 2), end-of-cycle refresh after the 2026-10-15 work · for tone-matcher-lead (end-of-cycle refresh, third run of the status-report skill)

Both render engines are now driven from code with no human in the loop, and one real song has been matched end to end on this machine. Helix Native 3.82 loads a new chain by an in-process file drop (about 66 s once per chain structure, macOS VST3, optional and off by default), renders in about 0.28 s per 2 s clip with flat memory (the host used to grow 4 to 11 GB and be killed), and block-serial rendering (one block per Native instance, chained) matches a single instance to -67 dB above 20 Hz on an 8-block chain. The HX Stomp (firmware 3.50) takes a whole generated preset into the edit buffer, is read back parameter by parameter after every write, and a snapshot-value bug that made a live delay run too wet is fixed. Stomp-versus-Native parity is -30 to -37 dB on clean and crunch presets, but the cab Early Reflections parameter does not match between the two engines (-3.6 dB at the value the search chose, -31 dB at 0), so anything meant for the pedal fixes it at 0 for now. The first real-song run (DS-Sample) produced a preset the human informally preferred over the loss's own first choice, which shows the loss is not trustworthy yet: no loss term is admitted, Gates 2 and 3 have no evidence, and no blind listening has happened. There is still no one-command song-to-preset tool, no Helix known-answer benchmark run, and the block-probe kit (offline, validated only on non-Helix blocks) has not yet been run through any engine. The human's next actions: run a guitar play-along capture on the pedal (user-DI path, hardware run pending), check the delay Mix and Time readback on the pedal after the fix, rule on the open proposals (Native 0.0 handling, snapshot-sync helpers in the preset writer, loudness term in the objective), and decide whether to start the overnight single-block capture once the stereo limit of the Native host is addressed.

  • The old and new reset paths disagree on randomly set parameters (levels 11.6 to 14.4 dB apart). The new path matches each file's own drop capture, so it is believed correct, but this is not independently confirmed. [DECISIONS 2026-10-15 native-engine host memory (open question)]
  • A stale template was reused for a second file with the same chain structure but a different unmapped parameter, which produced a false parity row (voided). Templates are now keyed by structure plus a hash of baked values and legacy templates are refused. [DECISIONS 2026-10-15 stale Native template; ledger/void.csv]
  • Native's reset does not clear delay lines: a chain with an enabled delay alternates between two renders (-19.7 dB) at the default 0.1 s pre-roll; 3 s fixes it (-62 to -65 dB). [ledger 2026-10-15T00:16:00+00:00]
  • Block-serial: the -22.6 dB untrimmed result is an artefact of each instance's 16-sample delay against modulation; trimming 16 samples per instance gives -67.1 dB above 20 Hz, but the full band is limited to -50 dB by sub-5 Hz content from the delay. An Amp+Cab block is not exactly an amp block followed by a cab block (0.021 dB, -72.7 dB gain-matched). An unexplained -67 dB floor appears once the amp follows other blocks. Dual cab, stereo paths and non-default settings are not tested. [DECISIONS 2026-10-15 T045; ledger 2026-10-15T19:21:10 blockserial-v0]
  • Native applies a drop-loaded file's block values and ignores its stale snapshot values (-330.1 dB versus -38.3 dB); capture now syncs snapshots to blocks. A block-bypass MIDI-CC encoding Native honours has not been found, so bypass patterns need one capture each. [ledger 2026-10-15T19:42:45; DECISIONS 2026-10-14 T018n stage 2]
  • Whole-preset state write is impossible (opaque encrypted records); the file drop is the supported route. The human clicked 'Change HC mode' once and ticked 'Don't ask again' to get a clean start state; no state edits were adopted. [docs/notes/native-spike.md; DECISIONS 2026-10-14 human rulings]
