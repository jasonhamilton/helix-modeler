Executive dashboard

Summary

The goal is a tool that listens to a recorded guitar tone and builds a matching preset for the HX Stomp pedal. The building blocks work and have just become faster: both sound engines run from code, checking a candidate on the pedal is about three times quicker, the software engine learns new sounds far faster, and a pedal layout bug is fixed. One real song has been taken through the whole chain by hand, and the owner found the result promising in an informal listen. What is missing is proof that the tool's own sense of what sounds similar can be trusted: on that song it could not tell its top two candidates apart, while the listener clearly preferred one. Until that is validated, automatic matching cannot be relied on, and no blind listening test has been run. The next step is to test that judgement against presets whose correct answer is known.

Biggest problem: The tone comparison is not validated

Critical Active Blocker

What is wrong
The tool scores how close two guitar sounds are with several measures, and none has passed the required accuracy test on audio from the real Helix engines.
Why it matters
Every automatic decision the tool makes (which preset is better, when to stop searching) depends on this comparison.
What it prevents
The optimiser cannot be trusted to pick a genuinely matching preset, so Gate 2 cannot be passed and automatic matching cannot be offered. On the one real song, the top two candidates scored 6.935 and 6.950 (lower is better), a gap too small to mean anything, while the listener clearly preferred one; the best score also swung from 7.7 to 22.7 depending on which clean guitar recording was used.

Impact

The library of measured blocks does not exist yet

Medium Risk

Problem
The per-block approach needs every effect block measured through Native, and the measuring kit has never been run on Helix.
Impact
Choosing amp and effect models from measurements (instead of trying them blindly) is not possible, which makes the search space larger than it needs to be.
Cause
The measuring kit was only finished offline on stand-in blocks. Native's current host is mono, so stereo blocks and dual cabinets cannot be measured; one unexplained accuracy floor remains when an amp follows other blocks.
Resolution
Render the measuring signal through Native for a few blocks first, set tolerances from repeat-render spread, then capture the library for mono blocks. Capturing is no longer an overnight job: 216 blocks took 84.6 s, and only 2 of 607 pedal models are refused by Native.
Owner
native-engine, then benchmark and search
Next step
Build the Native rendering of the measuring signal.

What works and what does not

Working and verified

  • Control Helix Native from code
    Working on macOS with Native 3.82; a 2-second clip renders in about 0.28 s with memory steady.
  • Control the HX Stomp from code and restore it
    Working on macOS, firmware 3.80; a whole preset is written, read back and checked, the pedal is restored exactly, and its blocks stay editable afterwards. Not yet checked: parity with Native on 3.80.
  • Read, write and check preset files
    Byte-for-byte round trip on both reference files; a smoke-test preset loaded on the pedal (reported by the owner).
  • Catch a mismatch between what was written and what the pedal holds
    Every parameter is compared after each write; this found a delay bug that is now fixed.
  • Native and the pedal agree on simple presets
    Three of four tested presets agree closely; the fourth, with an added effect, differs more. Breaks for one cabinet setting.

Implemented but not yet proven

  • Pick a preset that matches a recorded tone
    One song section tried; the score could not separate the top two choices; the listener's preference was informal.
  • Judge tone similarity reliably
    Tested on stand-in signals only, where the best measure picked correctly about 1 time in 8; no measure is admitted.
  • Isolate the guitar from a full mix
    Runs; quality scored only on an artificial mix.
  • Choose a clean reference guitar recording
    Picks from a library of 104 recordings; the benefit is unmeasured and the score varies a lot with the clip.
  • Search for blocks and settings
    Ran on one real song; recovery of known answers shown only with a fake engine.
  • Render a chain one block at a time
    One 8-block mono test chain agreed to within 67 dB above 20 Hz; dual cabinets and stereo untested.
  • Measure each block's behaviour with a test signal
    Validated on 14 non-Helix test blocks; never run through Helix.
  • Record the player's own guitar alongside the song
    Built and tested with fake devices; some takes exist; accuracy not measured.

Missing or not working

  • Turn a song into a pedal-verified preset with one command
    Not implemented; the steps are run by hand.
  • Produce up to three tone snapshots from one song
    Not implemented end to end.
  • Run blind listening sessions
    The session tool is not built.
  • Run the known-answer benchmark on Helix audio
    Not run; the set has not been rendered.
  • Library of measured blocks
    Not started.
  • Learned predictor for good starting points
    Not started.
  • Pedal control on Windows or Linux
    Unverified; no machine available.
  • Stereo blocks and dual cabinets in Native
    The Native host is mono only.

  6. Stomp: one engine session serves the whole batch, so the session overhead is paid once, not once per test (T061)
  7. Native: a search test is a render plus its score; the pool figures count both together (tests per second, 3 s pre-roll included), so no separate scoring time is added
  8. Native captures: the per-chain time is the wall-clock of 3 editor sessions running in parallel divided by the chains captured, with the per-parameter checks switched off

Purpose. Render a DI clip through a candidate preset offline in Helix Native, fast enough to be the searching engine.

Done when. A NativeEngine behind the frozen interface renders any chain structure the search needs at a measured cost, loads candidates without a GUI step per candidate, agrees with the Stomp within a measured null residual, and has run a full synthetic recovery pass.

Functionality today (partial).   • A stale template was reused for a second file with the same chain structure but a different unmapped parameter, which produced a false parity row (voided). Glossary

blind A/B
A listening test where the listener does not know which option is which.
block
One element in a preset's chain: an amp, cabinet, drive pedal, delay and so on.
capture
The one-off step that teaches Helix Native a new chain: the preset file is loaded into its editor and the resulting state is recorded.
CMA-ES
An optimisation algorithm used to search for suitable settings.
dB
Decibel, a logarithmic loudness or level-difference scale.
DI
Direct Input: a clean, unprocessed guitar recording, before any amp or effects.
DSP
Digital Signal Processing: the audio calculations inside amps and effects.
Early Reflections
A cabinet setting that adds the first short echoes of the room.
EULA
The software licence agreement shown when installing a product.
firmware
The software running inside the pedal.
fw
Short for firmware, the pedal's built-in software. The pedal was on version 3.50 until 2026-10-15 and is now on 3.80.
gate
A milestone with a written checklist and a human sign-off.
golden file
A reference preset file the owner exported from HX Edit or Native, used to check that our own files follow the same layout.
held-out
Test items not used when tuning, so the result is not flattered by tuning.
Helix Native
Line 6's software version of the Helix sounds; it runs as a plugin and renders audio offline.
Hum and Ripple
Two amp settings that add a mains-hum style noise. The noise runs freely, so it differs between renders of the same preset.
HX Edit
Line 6's editing program for the pedal; it also imports preset files.
HX Stomp
The Line 6 guitar-effects pedal this project targets.
known-answer set
A test set made by rendering presets we already know through Helix, so we can check whether the tool recovers them.
ledger
The project's append-only record of measured runs; a claim without a row did not happen.
loss
The score the optimiser tries to lower: how different two sounds are. Lower is a closer match.
MIDI CC
A control message that moves one knob or switch from software.
null residual
What is left when one recording is subtracted from another that should match. Reported in decibels below the signal; the more negative, the closer.
parity
Agreement between the two engines: the same preset is rendered on both and the recordings are compared.
Path A and Path B
The two signal paths of the HX Stomp. Using both at once renders two chains in one pass.
pre-roll
Extra audio played before the part that is recorded, so delays and reverbs start from the same state every time.
preset
A saved sound: a chain of amp, cabinet and effect blocks with their settings (an .hlx file).
readback
Reading the pedal's settings back after writing them to confirm they match.
render
Play a test signal through a preset and record the audio that comes out.
render pool
Several copies of Helix Native running at once, each rendering a different candidate, to finish a batch sooner.
search test
One candidate setting tried by the search: it is rendered and then scored against the target.
separation
Splitting a full mix into instruments so the guitar can be analysed alone.
session close
The last message a control program sends to the pedal when it is done. Without it the pedal stays in editing mode and its blocks cannot be edited by hand.
snapshot
One of up to three stored variations of a preset that the pedal can switch between.
stand-in signals
Test audio made by ordinary software effects instead of Helix. Useful for early checks; not proof the method works on Helix.
tone comparison
The loss: the combined measures of how similar two guitar sounds are.
trust check
A test of whether a measure puts the true preset first among many candidates.
wall-clock
Real elapsed time on a clock, as opposed to computing time.
